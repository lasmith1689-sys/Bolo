# Bolo on TestFlight (no Mac needed)

GitHub's Mac build servers build Bolo and upload it to TestFlight. Most of the setup is already
done:

| What | Value | Status |
|---|---|---|
| App ID | `com.lasmith1689.Bolo` (no capabilities) | registered |
| App Store Connect app | Bolo | created |
| TestFlight group | `Me`, internal, automatic distribution | created |
| Team ID | `U3CTV4FLKM` | in `Config/Shared.xcconfig` |
| Secrets | `APPLE_TEAM_ID`, `ASC_KEY_ID`, `ASC_ISSUER_ID` | added |
| Secret | `ASC_KEY_P8` | **add this one** (below) |

## 1. Add the API key's private key

Open [the repository's Actions secrets](https://github.com/lasmith1689-sys/Bolo/settings/secrets/actions)
(**Settings** ▸ **Secrets and variables** ▸ **Actions**) and add a repository secret named
`ASC_KEY_P8` whose value is the whole text of the `AuthKey_XXXXXXXXXX.p8` file, including the
`BEGIN` and `END` lines. It must be the key whose Key ID is in `ASC_KEY_ID`, with **Admin** access
(that's what lets GitHub use Apple's cloud signing, so there are no certificates to manage).

- **Windows:** right-click the file ▸ **Open with** ▸ **Notepad**, then Ctrl+A and Ctrl+C.
- **iPhone:** in Files, rename it to `AuthKey.txt`, open it, then **Select All** ▸ **Copy**.

GitHub encrypts secrets and hides them from logs. Never paste the key into a chat, an issue, or a
commit: this repository is public.

## 2. Ship a build

Builds go to TestFlight only when you ask, in either of two ways:

- On GitHub, open **Actions** ▸ **TestFlight** ▸ **Run workflow** ▸ **Run workflow**.
- Push a commit to `main` whose message contains `[ship]`.

Building and uploading takes about 10 to 15 minutes. Apple then processes the build, usually within
5 to 30 minutes, and TestFlight on your iPhone offers it (the `Me` group gets every build
automatically). Each build works for 90 days.

Every other push to `main` runs **CI** instead: unit tests, a Simulator build and launch test, and
an App Store archive that stops with "Nothing was uploaded".

## 3. Install

Install **TestFlight** from the App Store on your iPhone, sign in with the same Apple Account, and
tap **Install** next to Bolo. Later builds arrive as updates in TestFlight.

## New recordings

The recorded voices are generated by the **Audio** workflow, which runs by itself when
`content.json` changes and commits the clips. That commit doesn't start CI or TestFlight: push any
ordinary commit afterwards, then ship a build as above. To re-record everything, open **Actions** ▸
**Audio** ▸ **Run workflow** and tick **Re-record every clip**.

## If a build fails

The failed run ends with a one-line explanation:

| Message | Fix |
|---|---|
| "App Store Connect has no app with bundle ID…" | The app record must use `com.lasmith1689.Bolo` exactly. |
| "Check the API key…" | The key needs **Admin** access, and the three `ASC_` secrets must come from the same key. |
| "That build number was already used" | Click **Re-run all jobs** (the build number is the run number plus the attempt). |
| "Bolo.app carries entitlements it should not need" | Something added a capability; Bolo needs none. |

Until `ASC_KEY_P8` is added, a TestFlight run only checks that the App Store version builds, and
ends with "Nothing was uploaded".
